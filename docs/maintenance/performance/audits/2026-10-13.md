## Основные пути

`code`: контроллер обновляет источники и отображение, затем планирует новый цикл
через 1200 мс (`src/stream-deck/controller.ts:573`). Анимация применяется только
к работающим и ожидающим ввода задачам, с отдельным периодом 200 мс. OpenCode
собирается по спросу каждые 5 секунд; T3 Code обновляется по спросу вместе с
контроллером. Codex уточняет владение по локальным файлам каждые 5 секунд и при
появлении ещё не разобранной отслеживаемой задачи. Средства запуска независимо
наблюдают поколение приложения и обеспечивают восстановление.

Измерение полных живых путей «нажатие → видимая реакция» и «запуск → готовые
кнопки» — `NOT_PROVEN`; приложения и физическое устройство не использовались.
Время внутри модели и внешних сервисов здесь не измерялось.

## Выбранные локальные эксперименты

1. Повторный разбор неизменившихся файлов Codex. `code`:
   `src/codex/session-ownership.ts` повторяет ограниченное чтение и разбор хвостов
   последних 128 и дополнительных отслеживаемых файлов. Платят процесс и человек,
   если обновление совпало с командой. Стоимость правки средняя: нужен ограниченный
   кэш успешного результата с проверкой метаданных и сохранением сроков свежести.
2. Одновременные запросы общего предка OpenCode. `code`:
   `src/opencode/collector.ts` публикует загруженную сессию после ответа, поэтому
   параллельные цепочки могут повторить запрос. Платят сервис, транспорт и плагин.
   Стоимость малая: объединять ожидающий запрос только внутри одного подключения
   и одного цикла. Проверять число запросов, одинаковые снимки, ошибки и новый цикл.
3. Повторный поиск завершений в очереди. `code`:
   `src/agents/active-queue.ts` обходит сессии для каждого завершённого кандидата.
   Платит процесс при больших каталогах. Стоимость малая: один индекс допустимого
   максимального времени по хосту и нормализованной идентичности на проекцию.
   Проверять время полного вызова, все шесть назначений, дубли и изоляцию источников.

Измерения и решения записаны в `../journal.md`. Проверка исходных JSON основной
сессией обязательна перед включением чисел в итог.

## Решения владельца

`code`: T3 Code создаёт SSH-процесс для каждого выбранного удалённого окружения
при обновлении (`src/t3code/ssh.ts:70`). Постоянное соединение или иной график
опроса могут экономить установление соединений, но меняют эксплуатацию и/или
свежесть. Ожидаемый выигрыш — `NOT_PROVEN`. Нужны согласованные удалённые замеры,
затем отдельное решение с ценой в сложности, ресурсах и восстановлении соединения.

- Повторная отправка неизменных картинок уже подавляется `lastImages`; кандидат
  отклонён по отсутствию лишней операции на этой границе.
- Перекрывающиеся обновления уже объединяются; нажатия одной кнопки упорядочены,
  разные кнопки независимы. Параллелизация фаз нарушила бы корректность.
- Увеличение интервалов, удаление проверок личности и ожиданий готовности
  отклонены: меняют свежесть или безопасность вместо удаления лишней работы.
- Межцикловый кэш регистраций, PID, настроек или HTTP-ответов отклонён: может
  задержать отзыв доступа и смену сервиса. Кэш ожидающего запроса внутри одного
  цикла не должен превращаться в такой кэш.
- Переписывание обнаружения модулей renderer не выбрано: выигрыш не измерен,
  совместимость требует живой проверки. Импорты уже могут кэшироваться движком.
- Карты OpenCode ограничены; подтверждения T3 очищаются. Утечка не установлена.
  Рост `LocalActivityIndex.acknowledgedCompletions` — отдельная гипотеза без
  измеренной цены и доказанной безопасной политики удаления.
- Полный обход истории Codex растёт с числом файлов. Уведомления/инкрементальная
  индексация требуют более широкого решения; сначала измерять оставшуюся цену
  обхода после удаления повторного разбора.
- Windows-средства запуска не исполнялись. Платформенные правки без такой
  проверки не выбраны.
