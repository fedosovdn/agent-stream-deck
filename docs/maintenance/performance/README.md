# Измерение производительности

Измерения выполняются последовательно на локальных синтетических данных. Настоящие
приложения, пользовательские файлы заданий и сохранённые подключения не нужны для
такого сравнения. Запросы к удалённым источникам, профилирование живых сервисов,
платные прогоны и установка сборки требуют отдельного согласованного объёма работы.

## Порядок сравнения

1. Установить зависимости через `npm ci`; требования и обязательные проверки
   перечислены в `CONTRIBUTING.md`.
2. Сохранить измерительный сценарий и исходные результаты в системном временном
   каталоге. Собирать исходный и изменённый модуль одинаковыми настройками
   `esbuild`: `bundle: true`, `platform: node`, `format: esm`, `target: node24`.
3. До правки выполнить три исходных прогона. Порог принятия — большее из 10% и
   `(максимум − минимум) / медиана`. Сравнивать пять чередующихся прогонов каждой
   версии; три допустимы при явно исчезнувшей операции или достаточно малом
   разбросе. Каждый изменённый прогон должен быть лучше каждого исходного.
4. Проверить поведение перед оценкой скорости. Измерять полный публичный вызов;
   отдельно указывать холодное и повторное выполнение, размер данных, число
   запросов/чтений, время, память и непроверенные ограничения.
5. Записать попытку в `journal.md`, включая отменённые изменения. Числа текущего
   аудита находятся в `audits/`, а не в этом руководстве.

## Сценарии и ограничения

- Codex: `CodexSessionOwnershipIndex.annotate` на временном дереве JSONL-файлов.
  Проверять неизменные файлы, дописывание, усечение, атомарную замену, удаление,
  точное владение, время завершения и удержание начала работы. Порядок обхода и
  проверки метаданных сохраняются; ошибки чтения нельзя кэшировать как успех.
- OpenCode: публичные `start`/`refresh` сборщика с подставными защищёнными файлами
  и HTTP-ответами. Общие предки, независимые подключения, ошибочные цепочки и
  следующий цикл должны сохранять свои результаты. Проверки личности, пределы
  объёма/глубины и отмена обязательны.
- Очередь: `projectActiveQueue` с готовыми снимками; сравнивать все назначения,
  порядок, дубли идентичностей, недопустимые времена и независимость источников.
- Отображение: заглушки источников и действий из `test/controller.test.ts`.
  Неизменная строка картинки уже подавляет повторную отправку. Измерение генерации
  SVG само по себе не доказывает скорость физического устройства.
- Запуск: только изолированные команды/процессы наблюдателя. Не запускать его
  против настоящей установки ради замера. Состояние поколения и резервирование
  времени восстановления защищают от повторных перезапусков.

Периоды опроса, ожидание готовности, порядок нажатия/отпускания, сроки свежести,
проверки личности и ограничения loopback — защитные условия. Их сокращение само
по себе не считается оптимизацией. Время внутри модели и удалённого сервиса
нужно учитывать отдельно от локальной обработки.

Полная сборка `npm run build` создаёт также автономные средства запуска.
После сборки выпускных артефактов выполнить `npm run audit:release`.
Автоматические проверки, проверку живого приложения и физического Stream Deck
всегда описывать отдельно.

## Независимые циклы источников

Перед изменением сохранить публичные исходники и хэши измерителя в отдельной
копии. Причинный сценарий проходит настоящие `OpenCodeSource`, `T3CodeSource`
и `DeckController`; Codex и SDK подставляются на публичной границе, процессы SSH
и HTTP — ниже настоящих транспортных проверок. Каждая сторона использует тот же
исполняемый Node и те же параметры сборки. Версию Node измерителя указывать
отдельно от версии полной проверки корректности.

По отдельности проверять холодный запуск, публикацию готовой среды и следующий
местный опрос при удержанной удалённой работе. До правок фиксировать длительности,
фазы местных изменений и настоящие защитные таймауты. Три местные ревизии должны
достичь подставного SDK до завершения удалённой работы. Измерять также задержку
третьей ревизии от готовности данных до первого изображения. Такой сценарий
показывает независимость при заданной искусственной задержке, а не скорость
настоящей сети. Исправленный до правок измеритель становится новым неизменяемым
контрактом; прежние неудачи сохраняются и не считаются выигрышем продукта.
Если ошибка измерителя найдена уже после реализации, явно записать эту
хронологию, сохранить прежние данные и повторить исходную серию на неизменном
старом коде с тем же исправленным измерителем. Такое исправление нельзя
представлять как зарегистрированное до изменения продукта или как его выигрыш.

Окончательные пять чередующихся пар выполняются целиком, без выбора отдельных
случаев и без параллельных тестов, сборок или действий с приложениями. В тех же
прогонах наблюдать здоровые одинаковые нагрузки: 17 местных OpenCode и смешанные
1 местная +16 SSH OpenCode +8 SSH T3. Считать запросы HTTP и обращения SSH
раздельно, отправки SDK, пробуждения, CPU, среднюю и максимальную память процесса,
фактический допуск. Счётчик HTTP не подменяет число SSH-запросов. Удерживаемый
запрос разрешает дополнительные местные циклы; их цену указывать отдельно.
Сравнить полные команды сборки и каждый готовый пакет. До прогона проверять,
что бюджет покрывает всю серию и обязательную автоматику; не сокращать число
случаев, длительности или допуски после получения результатов.

Независимость работы не требует отдельного физического таймера для каждого
владельца. Один периодический сигнал может запускать самостоятельные операции
Codex, квот и T3, если ожидающая работа любого владельца не задерживает сигнал
другим. Повторная отправка SDK и перепроекция очереди объединяют накопленные
изменения, сохраняя немедленную доступность уже готовых местных данных.
Защиты поколений и точного подтверждения проверяются отдельно управляемыми
публичными сценариями; одно ускорение не доказывает их корректность.

## Размер поставки

Для выпускного плагина использовать `npm run build:release`, для разработки —
`npm run build`: разработка сохраняет полный текст в карте и несжатый JS.
`validate` и `pack` пересобирают выпускной вариант; перед дальнейшей отладкой
подключённой папки снова выполнить обычную сборку или запустить `dev`.
В подключённой папке эти команды удаляют прежние файлы, включая журналы:
измерения и проверки выполнять в изолированных публичных копиях с настоящими
локальными зависимостями, не через ссылки на рабочий `dist`.

Измерять целый готовый пакет одним и тем же упаковщиком, отдельно JS, карту
и оба автономных ZIP. Детерминированный размер допускает одну пару; порог
принятия — 10% (`assumed`). Для окончательной проверки каждого изменения
создать копию итогового кода с отменой только этого изменения. README, остальные
параметры и инструмент сжатия должны быть одинаковыми. Изменение названия
картинки считать заменой публичного ресурса, а не доказательством сходства картинок.

Время фактических полных команд npm и публичных операций — защитные показатели,
если заявлен только выигрыш размера. Пять чередующихся пар: допустимое ухудшение
сборки max(10%, 10 мс), операций max(10%, 1 мс), максимальной памяти отдельной
команды max(10%, 16 MiB), все пороги `assumed`. Эти допуски не доказывают ускорение.
Для утверждения об ускорении остаётся правило раздела «Порядок сравнения».
Показание `/usr/bin/time -l` не подменяет пик памяти всего дерева процессов.

Распаковать результат, проверить состав, CRC и хэши общих файлов, публичные
ссылки README, режимы Mac-скриптов, внешний `ws` в Windows, правовые комментарии.
Исполнить чувствительные контракты с точными параметрами выпуска: функция
боковой панели в отдельном контексте, SDK-декораторы и пара ввода, автономный
запуск. Искусственное исключение готового JS должно разрешаться по собственной
карте до исходного файла, строки и колонки; нужны исходники той же ревизии.
Аудировать дополнительные ZIP явно, кроме трёх стандартных корней.
